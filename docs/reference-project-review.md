# QQPet 二开项目：玩法借鉴评估

本文记录源码调研、移植方案和分批落地验证。参考项目为 AnkioTomas/qqpet，本地 Git 快照 `6e2c8bf`；当前工程为 qq-pet。参考目录的工作区缺少部分源文件，因此通过 `git show HEAD:<路径>` 读取，不恢复或修改参考项目。本报告未运行参考项目，不把源码存在当成运行验收通过。

## 结论

优先做 **部位点击互动 → 陪伴任务 → 小游戏奖励**，让企鹅对操作有具体反应，再让这些操作积累成可领取的成果。第二批做 **旅行地图、奇遇、明信片和相簿**，建立值得回来看的收集玩法。农场和原版桌面小游戏有趣，但需要额外资源和 Flash 接口适配，应单独推进。

当前项目已经拥有喂食、清洁、看病、商城、打工、学习、签到/在线礼包、养鱼、密室入口和独立 SWF 游戏。AI 也已有宠物状态上下文和主动关怀。上述基础能力适合扩展，没必要重新替换整个养成系统。

## 值得搬的玩法

### 再次对照当前工作区的建议

这次复查读取参考项目固定快照的 `pet.ts`、`machine.ts`、`tasks.ts`、`harvest.ts`、`calendar.ts` 和 `ui/smallgame.ts`，并对照当前源码；没有启动参考项目，也没有把当前未提交代码视为正式发布版本。

- **让企鹅平时自己玩**：参考 `pet.ts` 在进入待机后等待 20～60 秒，80% 播放玩耍动画、20% 发起闲聊；`machine.ts` 在动作末帧切回待机。当前 `swfPet.js` 已有相同随机调度，后续重点是检查动作结束与回待机是否可靠，避免只增加随机动作却仍卡住。眼睛跟随鼠标要保留独立坐标桥。
- **桌面窗口层级**：参考 `main/window.ts` 除了 alwaysOnTop，还设置 screen-saver 层级和所有桌面可见；当前已采用该策略并同步菜单、气泡与操作栏。macOS 实际窗口层级验证为 1000，高于普通置顶的 3；显示恢复不抢焦点。参考项目有意不覆盖全屏应用桌面，当前保持同样行为。
- **优先补六种宠物参与的桌面游戏**：猜动作、吹泡泡、跳绳、捉老鼠、颠球、下一百层，比继续增加普通独立游戏更贴近“和企鹅一起玩”。参考实现包含多窗口创建/销毁、跨播放器调用、输入穿透和心情奖励；下一百层只提供幼年版本。当前接口与入口已接入，六种游戏已验证加载和原生输入，下一百层验证实际键盘移动；完整回合、真实成绩发奖及其他性别/年龄组合仍需继续验收。
- **把一次互动变成持续目标**：参考任务不只有每日四项，还包含摸企鹅 5/10/15/20/25 次，以及到访 5/10/15/20/25/30/35 座城市的奖励阶梯。当前已有每日任务和旅行记录，适合增加里程碑；需明确累计周期、奖励上限和一次性领取。
- **让回来看看有惊喜**：旅行照片、奇遇纪念品、节日和年度生日邮件共用现有邮箱与相簿。旅行链路已有实现；欢迎、生日与六种本地节日元宝礼物已接邮箱，按完整月日与年份去重并验证重复领取。随机食物/玩具礼包和更多日历事件仍待扩展。
- **农场配收获提醒**：当前农场已经新增正式窗口、入口和元宝预留/退出归还逻辑；真实购买、播种、收获和异常退出全流程仍需验证。参考收获提醒只在成熟作物、灾害或成熟鱼数量增加时触发，至少间隔 30 分钟，适合接现有气泡与免打扰设置。

推荐接下来按 **桌面小游戏 → 互动/旅行里程碑 → 节日礼物和收获提醒** 提升趣味性；农场并行完成已有适配的可玩验证。高清位图可以随后改善画面，但不是企鹅不再发呆的核心原因。

## 源码与资源核对

- 当前 `Action` 目录有 **352 个 interact/Interact SWF**。参考项目点位表引用 287 个动画变体，逐一检查文件存在性后，缺失数为 **0**。这验证了第一项可以复用当前素材，但尚未验证每个动作的画面、点位精度和互动效果。
- 当前游戏目录有 **24 个 SWF**。参考项目普通游戏清单按分类合计 **101 个条目**，另有 6 种原版桌面小游戏。其 README 写“98 个”，与当前 Git 快照清单不一致，实际搬运应以清单和可运行测试为准。
- 参考 Git 树记录有 **231 张相簿图片**、**1378 张 `@2x.png` 图片**。当前未发现 `@2x.png` 素材。高清素材主要改善边框、按钮等位图，不能等同于让全部企鹅 SWF 高清化。
- 抽查参考项目的 `Farm.swf`、跳绳主 SWF 和相簿照片，Git 中保存的是 **Git LFS 指针**，不是可播放/显示的文件内容。参考工作区也不完整。农场、桌面小游戏、照片相簿实施前，需要拿到真实资源并验证完整性。
- 参考 README 标注代码 GPL-3.0；原版美术/SWF 和旅行照片另有素材来源说明。移植记录应区分逻辑来源和资源来源。

## 怎么接到当前项目

沿用当前 Electron 多窗口、Vue、宠物数据与物品系统。参考项目使用 TypeScript、原生 DOM、单个大覆盖窗口和自己的 `window.qqpet` 桥，因此适合搬行为规则、配置表和资源适配思路；直接复制整个 UI 会引入第二套窗口与存档体系。

1. **先接互动**：在 `main` 的 `#move` 上增加 HTML 互动点层，Ruffle 继续鼠标穿透。只有待机且健康条件允许时显示；点击热点触发动作，拖动达到阈值时取消点击。给动画路由增加互动动作类型和回待机规则。按实际资源名处理目录大小写。
2. **再接任务与游戏奖励**：用统一事件记录“喂食成功、洗澡成功、互动成功、游戏结束”等。任务模块只消费成功事件；奖励与计数写入版本化的独立扩展字段，保留旧存档。日期刷新、计数和领取应由同一处管理。
3. **旅行独立成一个完整功能**：活动开始、离线恢复、提前结束、回归、奇遇、访问记录和明信片生成都明确一次性结算。第一版地图与文字明信片可不依赖照片包。
4. **农场/桌面小游戏单独做兼容验证**：先取得真实资源，再用最小测试窗口验证 Ruffle 输入、ExternalInterface、相对资源加载、退出和存档写入，确认能玩后接养成数据。

当前 `GrowUp.countdownActiveTime` 按在线 tick 推进活动；参考 `jobs.resumeTask` 会把关闭应用期间的时间加入进度。值得借鉴其离线完成体验，但需要单独定义停止成长、死亡、手动改时钟和重复启动时的规则，不能直接把离线时间累计到全部成长/消耗指标。

## 不建议照搬的细节

- **先扩游戏数量**：当前有 24 个游戏资源，先保证输入、键盘焦点、退出和奖励联动有用，再扩大目录。资源数量不是可玩数量。
- **再建一套 AI 聊天/Agent**：当前已经更贴合此方向。可借鉴参考 `ai.ts` 的台词改写：保留时间、数字和物品信息，失败回原版台词；不要另接一套模型配置。
- **全屏大覆盖窗口架构**：参考靠一个覆盖工作区的窗口做点击穿透，当前是可移动的小宠物窗口和独立弹窗。为搬玩法替换窗口架构，容易再次影响拖动、菜单、多显示器与焦点。
- **把参考奖励规则直接当定稿**：点位互动每次加 5～15 心情、普通游戏按打开时长发奖，都应结合当前养成速度调整；领取条件要在业务层校验，不能只靠按钮状态。
- **生日规则混用**：参考 `signin.birthdayGift` 按生日“日号”匹配，可能每月触发；`mail.deliverMails` 按月日和年份生成生日邮件。迁入时要先明确要月度纪念日还是年度生日。
- **货币和存档直接并行覆盖**：参考农场以余额差额结算，和当前多窗口/Agent 操作接在一起时，要保证同一处发奖扣款并避免重复结算。

### 当前落地状态

第一批代码已接入：右键菜单新增“陪伴与冒险”，支持身体部位互动、每天早上 6 点刷新的四个任务，以及现有小游戏的前台游玩奖励。互动点可显示、隐藏或关闭；任务与奖励存入 `pet.playroom`，沿用原来的宠物存档。

第二批旅行、地图、奇遇、明信片、邮箱和照片相簿已接入：支持 35 个目的地、离线计时、暂停成长、提前回家和一次性结算。231 张照片已通过 LFS 哈希核验，按目的地/通用池选择且不重复收集。规则测试覆盖重启、时钟回拨与生病/死亡取消；实际 Electron 验证地图完整显示、旅行期间企鹅保持可见、停止与回归、邮箱领奖和相簿图片。旅行界面已改用参考项目的独立窗口与 normal/vip 边框，详见验收记录。
